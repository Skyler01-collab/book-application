# Book Application

A small **Spring Boot REST API** for managing books. It demonstrates the full **CRUD** cycle (Create, Read, Update, Delete) using **Spring Data JPA** with an in-memory **H2** database, organised in the classic controller, service, repository layers.

![Java](https://img.shields.io/badge/Java-17-orange)
![Spring Boot](https://img.shields.io/badge/Spring%20Boot-3.4.4-brightgreen)
![Database](https://img.shields.io/badge/Database-H2%20(in--memory)-blue)

## What this project shows

- REST controller with `GET`, `POST`, `PUT` and `DELETE` endpoints
- JPA entity mapping (`@Entity`, `@Id`, `@GeneratedValue`)
- Spring Data JPA repository (`JpaRepository`) plus a derived query method (`findByTitle`)
- Layered architecture: **Controller -> Service -> Repository -> Database**
- Constructor-based dependency injection
- Boilerplate-free model class with **Lombok** (`@Data`, `@NoArgsConstructor`, `@AllArgsConstructor`)
- Zero-setup database with **H2** and its web console
- API testing with **Insomnia**

## How a request flows

```
Insomnia  ->  BookController  ->  BookService  ->  BookRepository  ->  H2 database
(HTTP/JSON)   (maps the URL)      (logic)          (Spring Data JPA)    (book table)
```

## Data model

The `Book` entity is mapped to a `book` table. The `id` is generated by the database.

| Field | Type | Notes |
|-------|------|-------|

## Getting started

### Prerequisites

- JDK 17 or newer
- Maven (optional, the wrapper is included)

### Run the application

```bash
git clone https://github.com/Skyler01-collab/book-application.git
cd book-application

# Linux / macOS
./mvnw spring-boot:run

# Windows
mvnw.cmd spring-boot:run
```

You can also open the project in IntelliJ IDEA and run `BookApplication`.

The API starts on **http://localhost:8080**.

> The database is in-memory, so all data is wiped each time the application stops.

## API endpoints

Base path: `/books/v1`

| Method | Endpoint | Description | Request body | Success response |
|--------|----------|-------------|--------------|------------------|
| `POST` | `/books/v1/addBook` | Create a book | Book JSON (no `id`) | `200 OK` with the saved book, including its new `id` |
| `GET` | `/books/v1/getBook/{name}` | Find a book by its **title** | none | `200 OK` with the book |
| `PUT` | `/books/v1/updateBook` | Update an existing book | Book JSON (with `id`) | `200 OK` with the updated book |
| `DELETE` | `/books/v1/deleteBook/{id}` | Delete a book by id | none | `204 No Content` |

## Try it with Insomnia

I tested every endpoint with [Insomnia](https://insomnia.rest/). To reproduce:

1. Create a new request collection called **Book Application**.
2. Add an environment variable so you can reuse the base URL:
   ```json
   { "base_url": "http://localhost:8080/books/v1" }
   ```
3. Create the four requests below. For the ones with a body, set the body type to **JSON**.

### 1. Create a book

`POST {{ _.base_url }}/addBook`

```json
{
  "title": "Clean Code",
  "author": "Robert C. Martin",
  "genre": "Programming"
}
```

Response (`200 OK`):

```json
{
  "id": 1,
  "title": "Clean Code",
  "author": "Robert C. Martin",
  "genre": "Programming"
}
```

### 2. Get a book by title

`GET {{ _.base_url }}/getBook/Clean Code`

(Insomnia encodes the space for you. In a browser or curl use `Clean%20Code`.)

Response (`200 OK`): the same book JSON as above.

### 3. Update a book

`PUT {{ _.base_url }}/updateBook`

```json
{
  "id": 1,
  "title": "Clean Code",
  "author": "Robert C. Martin",
  "genre": "Software Engineering"
}
```

Response (`200 OK`): the book with the new genre.

### 4. Delete a book

`DELETE {{ _.base_url }}/deleteBook/1`

Response: `204 No Content`.

### Prefer curl?

```bash
curl -X POST http://localhost:8080/books/v1/addBook \
  -H "Content-Type: application/json" \
  -d '{"title":"Clean Code","author":"Robert C. Martin","genre":"Programming"}'

curl http://localhost:8080/books/v1/getBook/Clean%20Code

curl -X PUT http://localhost:8080/books/v1/updateBook \
  -H "Content-Type: application/json" \
  -d '{"id":1,"title":"Clean Code","author":"Robert C. Martin","genre":"Software Engineering"}'

curl -X DELETE http://localhost:8080/books/v1/deleteBook/1
```

## JPA and Spring Data concepts used

| Concept | Where | What it does |
|---------|-------|--------------|
| `@Entity` | `Book` | Maps the class to a database table |
| `@Id` + `@GeneratedValue(IDENTITY)` | `Book.id` | Primary key generated by the database |
| `JpaRepository<Book, Integer>` | `BookRepository` | Gives `save`, `findById`, `deleteById`, `findAll`... with no SQL |
| Derived query `findByTitle` | `BookRepository` | Spring builds `SELECT ... WHERE title = ?` from the method name |
| `save()` on an existing id | `BookService.updateBook` | Updates the row instead of inserting a new one |
| Constructor injection | Controller and Service | Easier to test than field injection |
